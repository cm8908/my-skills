# 정민섭 기술 문서 스타일 가이드 (v-final)

Dnotitia LLM 팀 실험 보고서·기술 문서용. 실제 문서 2건에 대한 4차례 저자 수정 diff를 역공학해 도출했다.
독자 모델은 "이 도메인은 알지만 이 실험은 처음 보는 팀원". 목표는 그가 사전 맥락 없이 evidence와 conclusion을
구분하며 따라오게 만드는 것.

## 핵심 철학

**저밀도·고명시성.** 문장당 정보량을 최대화하는 논문 초록 스타일의 반대편.
정보를 공간적으로 펼쳐(불릿·들여쓰기·화살표) 독자의 파싱 비용을 문서 구조가 대신 지불한다.
문장이 하던 일(접속·인과·위계)을 레이아웃이 하게 만든다.

한 줄 요약: **화려한 압축보다, 논리 단계가 눈에 보이는 개조식 전개.**

이 가이드는 두 층으로 나뉜다. **구조 규칙(A)은 4라운드 연속 무수정으로 완전히 수렴**했으니 그대로 적용하면 된다.
**어휘 규칙(B)은 판별이 미묘**하니 B1의 원칙을 특히 정확히 이해할 것 — 과거에 이 부분에서 가장 많이 틀렸다.

## A. 구조 규칙 (수렴 완료 — 확신을 갖고 적용)

### A1. 1 불릿 = 1 명제
- 쉼표나 "~이고 / ~하며"로 이어진 복합 주장은 하위 불릿으로 분해한다.
- 괄호 안에 실질 정보(검증 사실·수치·원인)를 넣지 않는다 → 독립 하위 불릿으로 승격.
- 괄호의 허용 용도는 둘뿐: 용어 매핑 `비교군(arm)`, 짧은 정의 `Graft 체크포인트 (finetuned DNA + base MTP head)`.

### A2. 근거와 추론의 시각적 분리 — 이 스타일의 심장
- 관측 사실을 먼저 쓰고, 그로부터의 결론/추론은 `==>` 로 시작하는 별도 불릿에 쓴다.
- 전형적 패턴:
  ```
  * 관측: <사실>
      * <세부 근거 / 조건부 반박: "만약 ~였다면 ~했어야 함">
  * ==> <결론>
  ```
- 해석·추정에는 hedge를 건다: "~로 보임", "~라고 볼 수 있음", "~로 기록". 데이터는 중립적으로, 해석은 해석임이 드러나게.

### A3. 화살표는 범용 논리 연결자 (`==>` 와 `→`)
- `==>` : 관측에서 끌어낸 **결론/함의** ("그러므로"). 판독의 핵심 주장에 쓴다.
- `→` : 값의 변화(`base→DNA`, `0→1`), 또는 가벼운 **전이·후속** ("그다음 / 으로 이어짐").
- 중요: 화살표는 결론뿐 아니라 **실험 간 인과 사슬**도 표시한다.
  예: "멀티모달 점수는 백본 이동을 과소평가함. 따라서 perception-bound 문제로 실험 확장 필요 → 4b OCRBench, DocVQA"
  ("이 관측이 다음 실험을 낳았다"는 서사를 문서에 심는 것.)

### A4. 개조식 종결
- 불릿 종결은 조사·어미가 완전한 개조식: "~함", "~했음", "~높음", "~것임", "~뿐".
- 조사를 생략한 명사 나열 금지: "비트 단위 동일 검증"(X) → "비트 단위로 동일한 점 확인했음"(O).

### A5. 번호 vs 불릿의 경계
- **순차 절차**(먼저 A, 그다음 B, 마지막 C) → 번호 매김. 하위 단계도 중첩 번호.
  예: "1. residual state를 교체하고 (1-1. 양방향 스윕) 2. A–D 확률로 판독 3. 컨트롤 3종을 함께 돌림"
- **병렬 나열**(순서 없는 항목들) → 일반 불릿.
- **개수가 선언된 열거**("3가지로 검증함:") → 번호.

### A6. 제목은 자기완결적으로
- 조어·개념은 제목에서 즉시 정의: `## Graft 체크포인트 (finetuned DNA + base MTP head)`.
- 결과 섹션 제목은 실험 라벨과 연결: `## 실험 A 결과: 인터페이스는 손상 없음`, `## L2 — behavior: MG 분해`.
- 측정 조건·통계 세팅 같은 방법론 메타데이터는 제목이 아니라 본문 첫 불릿에: `* 측정: vLLM /metrics 실측, k=1 기준`.

### A7. 표 옆에는 반드시 기호 해제 블록
- 표의 열 헤더가 축약 기호(S_with, ΔMG, relL2 등)면, 표 바로 앞이나 뒤에 **"지표 설명" 블록**을 둔다.
  예: "S_with: 이미지와 함께 입력 / S_blind: 이미지 없이 텍스트만 / delta: DNA − base 차이 / MG: Multimodal Gain"
- 원칙: 표는 데이터만, 기호를 사람 말로 푸는 것은 산문의 몫. 표 셀 안의 서술은 개조식 분해하지 않고 문장만 다듬는다.

### A8. 볼드 규율
- 볼드는 핵심 주장, 핵심 질문, 헤드라인 수치·라벨 전용.
- 문장 중간 단어 강조("통과한 **후**의")에는 쓰지 않는다.

### A9. 정보 밀도의 비대칭
- **TL;DR·배경**: 최단 경로로 핵심 질문/결론에 도달. 구현 배경·역사 서사는 과감히 삭제 가능.
- **방법·결과·한계·재현**: 기록이 목적. 수치·세팅·파일 경로·인용을 절대 삭제하지 않고 구조만 재편한다.
- 표 데이터와 수식은 원문 그대로 보존.

## B. 어휘 규칙

### B1. 용어 선택의 근본 원칙 — "무엇을 표준 사고 단위로 쓰는가" (가장 자주 틀리는 지점)

**한국어 역어가 존재하는지를 보지 말 것.** 판별 기준은 **"이 도메인 실무자가 이 개념을 평소 어느 언어로 사고/발화하는가"** 이다.

멀쩡한 한국어 역어가 있어도, 논문·코드·랩 미팅에서 영어로 다루는 개념이면 **영어를 그대로 쓴다**:
- 영어 유지: `weight`, `behavior`, `representation`, `layer`, `median`, `initialization`, `dimension`, `position`, `response`, `baseline`, `weight tensor`, `self-generated`, `hidden state`, `stylistic artifact`, `visual-conditional`, `perception-bound`, `sharpening`, `drift`, `flip`, `rotation alignment`, `residual state`
- 이들은 각각 "가중치·행동·표현·레이어·중앙값·초기화·차원·위치·응답" 같은 역어가 있는데도 **영어가 표준 사고 단위라 영어로 쓴다.**

반대로, 아래 세 부류는 표준 사고 단위가 아니므로 **쉬운 한국어로 교체하거나 제거**한다:
1. **은유·비유적 압축**: "포렌식→(가중치) 대조", "계측기→측정할 수 있음", "진원지→발생 위치", "스트림 출구→출력 전단계"
2. **사내 은어·즉석 조어·즉석 축약**: "델타→변화량(또는 delta로 명시)", "spec decode→speculative decoding", "near-tie 플립→확률이 거의 같은 토큰이 flip하는 케이스", "4-arm→4가지 방법론 비교", "Tier-1/2/3→실험 A/B (또는 서술)"
3. **멋 부린 한자어**: "무손상→손상 없음", "잔존함→남아 있음", "귀속→분리/구분", "시맨틱스→(삭제)"

일상 학술어("검증·산출·재현·확증·정정·폐기")는 그대로 둔다. 이것도 이 도메인의 표준 한국어 사고 단위다.

정리하면 3층:
- (표준 영어 사고 단위) → 영어 그대로, 필요시 영어 동사화("sharpening함", "drift시킨", "flip하는")
- (표준 한국어 사고 단위 = 일상 학술어) → 한국어 그대로
- (은유 · 사내 은어 · 즉석 조어/축약 · 멋 부린 한자어) → 쉬운 한국어로 풀거나 삭제 (소급 적용: 이전 버전에 있던 것도 제거)

첫 등장 시 자연스러운 한국어가 있는 표준어는 괄호 매핑을 남긴다: "비교군(arm)", "회전 정합(rotation alignment)".

### B2. 압축 복합어 해체
- 동작성 명사+명사 결합 → "~된/~한 + 완전한 명사": "고정 코퍼스→고정된 코퍼스", "이식 head→이식된 MTP head", "실서비스→실제 서비스".
- 명사구 압축 → 부사+동사절: "자동 유도가 실패함→자동으로 유추하는데 실패함", "분리 측정→분리하여 측정".

### B3. 지시 대상 복원 — 반복을 두려워하지 않음
대명사·축약 지시가 나올 때마다 머리 명사를 다시 써준다. 반복의 비용 < 모호함의 비용.
- "가중치 없이"→"MTP head의 weight tensor 없이", "이식 절차"→"MTP head 이식 절차", "후속 제안"→"후속 실험 제안"
- "이 바운드 안에서"→"이 노이즈 범위 안에서" (지시어가 가리키는 대상을 이름으로)
- 수식어는 올바른 머리어에: "150개 on-policy 프롬프트"(X, 프롬프트가 on-policy인 게 아님) → "150개의 프롬프트에 대해 on-policy 실행"(O)
- 짧은 정의를 능동적으로 보강: "blind"→"이미지 없이 blind", "judge"→"LLM judge" (독자가 걸릴 지점에 정의를 심는다)

### B4. 동사의 중립성 vs 담화 표지 — 반드시 구분
- 현상 서술에는 가치 평가 동사·표현 금지: "순위 일치를 해쳤다"(X)→"순위 일치를 drift시켰다"(O), "손실이 −5.2pt에 그치고"(X)→"−5.2pt 하락"(O). 평가가 필요하면 `==>` 결론 라인에서.
- 단, 논리적 대비·의외성을 표시하는 담화 부사는 적극 사용: "**정작** weight tensor 없이", "**오히려** +0.8". 하락 맥락의 상승처럼 의외인 값에는 담화 표지를 오히려 추가한다.

### B5. 의미 정밀성
단어가 실제 현상과 일치해야 한다: config 값은 유도(derive)가 아니라 "유추(infer)"되는 것,
바운드 안에서 일치하는 것은 "대조"가 아니라 "차이", 가설을 "귀속"이 아니라 "분리/구분".

### B6. 구체적 아티팩트 참조
서술 대신 실제 코드/파일/지표 이름을 백틱으로 직접 인용: "오프라인 하네스의"→"`mtp_offline.py`의".
지표 이름도 코드상 이름 그대로: `corpus_hit`, `verifier_hit`.

## D. 작성/윤문 후 점검 체크리스트

1. "~이고 / ~하며"로 두 명제가 이어진 불릿 → 분해 (A1)
2. 괄호 안 실질 정보 → 하위 불릿 승격 (A1)
3. `==>` 없이 관측·결론이 한 문장에 섞임 → 분리, 해석에 hedge (A2)
4. 관측이 다음 실험을 낳은 지점에 `→` 사슬이 있는가 (A3)
5. 축약 기호 열 헤더 표 옆에 "지표 설명" 블록이 있는가 (A7)
6. 순차 실험 절차가 산문으로 뭉쳐 있는가 → 번호화 (A5)
7. **용어: 표준 영어 사고 단위를 한글로 풀지 않았는가 / 은유·은어·즉석조어를 영어인 채 두지 않았는가 (B1 — 양방향 점검)**
8. "이/그/해당"의 대상이 명시돼 있는가 → 머리 명사 복원 (B3)
9. 독자가 걸릴 용어에 짧은 정의가 붙어 있는가 (B3)
10. 가치 평가 동사가 현상 서술에 있는가 → 중립 동사로 (B4)
11. 의외인 값(하락 중 상승 등)에 담화 표지("오히려")가 있는가 (B4)
12. 문장 중간 볼드 → 제거 (A8)
13. 같은 개념이 다른 단어로 불리는가 → 통일

## E. 과교정 경계 (특히 주의)

- **B1은 양방향 함정이다.** "한자어니까 풀자"도, "영어니까 유지하자"도 둘 다 틀린 휴리스틱. 판별은 항상 "이 도메인 실무자의 표준 사고 단위인가" 하나뿐. weight는 영어로 유지, 포렌식은 한국어로 교체 — 겉보기엔 반대지만 같은 원칙이다.
- 일상 학술어("검증·산출·재현·확증")는 건드리지 말 것.
- 담화 표지("정작·오히려")까지 제거하면 과교정 (B4).
- 방법·결과·한계·재현 섹션의 수치·세팅·경로·인용 삭제 금지. 삭감 허용은 TL;DR·배경뿐 (A9).
- 표 데이터·수식·status 매크로 등 Confluence 네이티브 요소는 원문 보존.
- 이 스타일은 무미건조함이 목표가 **아니다.** 가치 평가는 빼되, 저자가 독자를 위해 정의·수치·대비 표지를 능동적으로 보강하는 것은 권장된다 (윤문가 아닌 저자의 개입).

## F. 최우선 규칙 (충돌 시)

**사용자가 직접 쓴 최신 버전의 표현이 이 가이드보다 항상 우선한다.**
diff가 이 가이드와 충돌하면 사용자 수정을 정답으로 삼고, 그 신호로 이 가이드를 갱신할 것을 제안한다.
이 가이드 자체가 4라운드 diff로 진화해 왔으며, 앞으로의 수정으로 계속 정교화되는 살아있는 문서다.
